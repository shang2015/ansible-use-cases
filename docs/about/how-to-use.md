# How to use this site

## In a customer conversation

1. Start from the customer's domain, for example **Network** or **Security**, and scan the use case list for the outcomes they care about.
2. Every use case is one table: **Description** frames the conversation, **Collection** and **Key content** show what is already built and supported, and **Notes** cover variations and related use cases. A **Certified** or **Validated** badge means the content is on Automation Hub and covered by the subscription.
3. Under **Product use cases** on the same domain page, find the customer's product. Its collection page lists what the collection automates, grouped by outcome, with every supported component and the modules that manage it.
4. To leave something behind, download the domain's PDF from [Downloads](../downloads/index.md). It has the same tables in the format of the original *Ansible Automation - Use Cases* document.

## When a customer names a product

Search the [Module Explorer](../explorer.md) for the product or the task (for example `fortios policy` or `vm snapshot`). Every result links to the module's documentation on Automation Hub and to its source.

For security and observability tools, open [Vendor collections](../vendors/index.md) to see where the vendor's content comes from, how it is supported and when it was last updated.

## Support levels

| Badge | Meaning |
|---|---|
| <span class="uc-badge uc-certified">Certified</span> | Published on Automation Hub. Tested and supported by Red Hat together with the partner. |
| <span class="uc-badge uc-validated">Validated</span> | Red Hat Validated Content on Automation Hub. Opinionated, tested roles and playbooks built by Red Hat for common scenarios. |
| <span class="uc-badge uc-galaxy">Galaxy (community)</span> | Available on Ansible Galaxy. Not supported by Red Hat, although the vendor may support it. |
| <span class="uc-badge uc-github">Vendor GitHub only</span> | Published only in the vendor's own repository. |
